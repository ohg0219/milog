# milog

CloudWatch 에 JSON 한 줄로 쌓이는 로그를 **브라우저에서** 읽는다.
Log4j2 `JsonTemplateLayout` + OpenTelemetry 규약을 알고 읽어서, 레벨·소요시간을 컬럼으로 세우고
요청(trace)마다 색을 달리하고 span 중첩을 들여쓰기로 보여준다.

```bash
npm i -g @ohg0219/milog
milog
#   milog  →  http://127.0.0.1:52413/?t=ae644d04-…
```

설치는 스코프 이름으로, **명령은 `milog`** 로 쓴다.

로컬 서버를 띄우고 브라우저를 연다. 프로필·로그 그룹 선택부터 실시간 추적까지 전부 화면에서 한다.

```
16:49:00.023 INFO  5b434bc396de ● GET /orders/detail                    58ms
16:49:00.022 INFO  5b434bc396de   ↳ OrderService.findDetail              2ms
16:49:00.022 INFO  5b434bc396de     ↳ SELECT orders                      1ms
16:49:00.021 INFO  5b434bc396de     · OrderService  재고 확인 완료
16:50:00.014 ERROR a41c9d0e77b3 ● GET /orders/pay                     1204ms  ERROR
      ✗ java.lang.IllegalStateException: 상품 정보를 찾을 수 없음
```

## 무엇이 좋은가

- **trace_id 를 클릭**하면 요청 하나가 span 트리로 열린다. waterfall 로 어디서 시간이 새는지 본다.
- **타임라인**에서 에러가 몰린 구간이 빨갛게 보이고, 끌어서 그 구간만 볼 수 있다.
- 긴 `db.statement`·스택 트레이스·객체 덤프를 **자르지 않고** 본다.
- 한글 로그가 안 깨진다 (AWS CLI 를 거치지 않고 SDK 로 직접 읽는다).

## 요구 사항

- **Node 22.12 이상**
- `~/.aws/config` 에 프로필이 있고, 그 자격증명으로 CloudWatch Logs 를 읽을 수 있을 것

프로필이 없으면 만든다:

```bash
aws configure sso --profile my-logs
```

| 프롬프트 | 예시 |
|---|---|
| `SSO session name` | `my-sso` |
| `SSO start URL` | `https://<조직>.awsapps.com/start` |
| `SSO region` | `ap-northeast-2` |
| 계정·역할 | 로그가 있는 계정 / CloudWatch Logs 읽기 권한이 있는 역할 |
| `CLI default client Region` | 로그 그룹이 있는 리전 |

- `[profile ...]` 바로 위의 `#` 주석은 목록에서 설명으로 쓰인다.
- 토큰이 만료되면 `aws sso login` 을 알아서 띄운다.
- 프로필이 많으면 `--profile-prefix <접두어>` 로 목록을 좁힌다.

잘 안 되면 **`milog doctor`** 부터. Node·한글 출력·프로필·자격증명을 차례로 짚어 준다.

## 명령

```
milog                        브라우저에서 보기 (기본)
milog -p my-logs -g qa-web   프로필·그룹을 미리 고른 채로 시작
milog --port 8080 --no-open  포트 고정, 창은 직접 열기
milog doctor                 환경 진단
```

| 옵션 | 뜻 |
|---|---|
| `-p, --profile` | AWS 프로필 (부분일치) |
| `-g, --group` | 로그 그룹 (부분일치·반복·콤마) |
| `--region` | 리전 (미지정 시 프로필의 region) |
| `--profile-prefix` | 프로필 목록을 접두어로 좁히기 |
| `--port` | 기본 `0` = 빈 포트 자동 |
| `--no-open` | 브라우저를 자동으로 열지 않음 |
| `--idle-minutes` | 접속이 없으면 종료 (기본 30, `0`=무제한) |

## 화면

```
[my-logs › qa-web +1 ▾] │ [실시간|에러|검색] [자동 스크롤 ●] [날짜 2026-08-13 ~ 08-14 ▾] [조회]      [⚙]
[검색어 ...........................................]      ← 검색일 때만
```

왼쪽 **소스 pill** 을 누르면 프로필·로그 그룹을 고르는 팝오버가 열린다.
프로필을 바꾸면 그룹 선택은 비워진다. 조작부는 전부 왼쪽에 모여 있고, 화면 아래에는
타임라인 말고 아무것도 없다 — 상태는 전부 상단 한 곳에서 읽는다.

`자동 스크롤` 을 끄면 새 줄이 와도 보고 있던 위치가 안 밀린다.

### 모드는 셋이다

| 모드 | |
|---|---|
| **실시간** | 5분 전부터 계속 따라간다. 누르면 바로 시작 |
| **에러** | 날짜 구간 안에서 **ERROR·FATAL 과 예외**만 |
| **검색** | 날짜 구간 안에서 **검색어**로 찾는다. 비우면 그 구간 전체 |

각 모드는 보낼 조건을 **하나만** 갖는다. 안 보이는 칸의 값은 아예 안 보낸다 —
감춘 조건이 몰래 걸리면 왜 안 나오는지 알 길이 없다.

#### 검색과 에러를 왜 섞지 않나

CloudWatch 는 **텍스트 패턴과 JSON 패턴을 한 요청에 못 섞는다.** 둘을 합치면 검색어가
원본 줄 전체가 아니라 `message`·`logger`·`span.name` 세 필드만 훑는 좁은 검색으로 바뀐다.
같은 trace_id 로 실측하면 검색어만 줬을 때 37줄이 나오던 것이 **에러를 함께 켜면 0줄**이 된다
(그 요청에 ERROR 가 분명히 있는데도). 느려서가 아니라 **답이 틀려서** 나눴다.

### 날짜

날짜 pill 에 빠른선택(`오늘` `어제` `최근 2일` `최근 7일` `이번 주`)과 달력이 있다.
시작일·종료일을 차례로 누르면 범위가 잡히고, **하루 단위**로 `00:00:00 ~ 23:59:59` 가 된다.
미래 날짜는 고를 수 없다.

**조회는 `[조회]` 를 눌러야 나간다.** 모드를 바꾸거나 날짜를 고르는 것만으로는 아무 요청도
안 나간다. 진행 중에는 `[중지]` 로 언제든 끊을 수 있고, 받은 만큼은 화면에 남는다.

### 조회 중에는

```
[실시간|에러|검색] [날짜 ▾]  ● 조회 중 2.6초 · 3,490건 · 요청 5회 · 3.1 MB  [중지]
▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░
```

**진행률(%)은 일부러 안 그린다.** CloudWatch 는 매치가 0건인 페이지에서 스캔 위치를
알려주지 않아, 에러처럼 드문 조건이면 진행률이 멈춘 채 거짓말이 된다. 대신 **언제나
움직이는 값**만 쓴다 — 경과(0.25초마다 브라우저가 셈) · 요청 수 · 수신량 · 건수.

결과가 거의 없을 때도 `조회 중 3.3초 · 0건 · 요청 6회 · 2 KB` 처럼 경과와 요청이 계속
올라가므로 멈춘 것으로 오해하지 않는다.

**실시간에는 막대가 없고 남은 시간이 뜬다** — `● 추적 중 58:53 · 30건 · 요청 25회 · 45 KB`.
60분 뒤 자동으로 멈추며(5분 남으면 노란색), `[시작]` 을 누르면 이어서 따라간다.

**끝나도 결과는 안 지운다.** '몇 건을 얼마나 받았나' 는 조회가 끝난 **뒤에** 보고 싶은
값이기 때문이다. 초록이 걷히고 회색으로 남는다:

```
조회 완료 21.6초 · 7,225건 · 요청 12회 · 8.2 MB
추적 중지 · 25건 · 요청 3회 · 30 KB
```

다음 조회를 시작하면 초기화된다.

### 타임라인

```
타임라인 · 30분 단위 · 검색어 일치   에러 41   7,714건   선택 08-13 17:00 ~ 17:30 · 132건  [선택 해제]
▁▁▂▁▃▃▄▆▅▇█▆▄▃▄▅▇▆██▓▓█▆▃▂▂▁
08-13 00:00        08-13 05:59        08-13 11:59        08-13 17:59        08-13 23:59
```

- **에러·예외가 있는 구간은 빨갛다.** 수천 줄을 눈으로 훑지 않아도 어디가 터졌는지 보인다.
- **끌어서 구간을 고르면 목록이 즉시 좁혀진다.** 막대 하나를 클릭하면 그 칸만.
- 이건 **받은 이벤트를 세는 것뿐**이라 CloudWatch 요청이 하나도 안 늘어난다.
  구간을 고르는 것도 재조회가 아니라 화면에 있는 것을 거르는 것이다.
- 끝의 `전체` / `검색어 일치` / `에러·예외만` 은 이 막대가 무엇을 센 것인지 말한다.

| 조작 | |
|---|---|
| **타임라인 드래그** | 그 구간으로 목록 좁히기 (요청 없음) |
| 목록의 **trace_id 클릭** | 상세 열기 |
| 상세에서 **span 줄 클릭** | 그 하위를 접기/펴기 (접으면 `+N`) |
| 긴 값의 **`⋯ 더보기`** | 접힌 값 펼치기 |
| 상세 **왼쪽 모서리를 끌기** | 패널 폭 조절 |
| **목록 클릭** 또는 `Esc` | 상세 닫기 (팝오버가 열려 있으면 그것부터) |

## 읽는 법

| 마커 | 뜻 |
|---|---|
| `●` | **wide** — 요청 하나의 루트 span |
| `↳` | **call** — 그 안의 내부 호출 |
| `⇡` | 부모 span 이 조회 범위 밖 |
| `·` | **narration** — `log.info` 류 |
| (없음) | JSON 이 아닌 평문 줄. **한 글자도 손대지 않는다** |

- **trace_id 컬럼**은 요청마다 색이 다르다. **뒤 12자리**를 보여주는데, 앞 8자리는
  생성 시각이라 같은 시각의 요청끼리 구분이 안 되기 때문이다.
- 들여쓰기는 span 중첩 깊이다.
- **소요시간**은 느릴수록 눈에 띈다 (`MILOG_SLOW_MS` 기본 1000ms).

### 속성은 목록에 안 싣는다

목록은 **훑는 화면**이다. 한 줄에 속성을 세 개씩 잘라 붙여 봐야 시간·이름·소요시간을
읽는 눈만 흐린다. 궁금하면 **trace_id 를 눌러 상세에서 전부** 본다.

```
11:45:00.121 INFO  55ea20212d8d ● BatchDevController.renew                6ms
11:45:00.117 INFO  55ea20212d8d   ↳ SchedulerService.findRenewNotiTarget  1ms
11:45:00.116 INFO  55ea20212d8d     ↳ SELECT orders                       1ms
```

상세에서도 두 가지는 걸러낸다. 단 **사용자 정의 속성은 절대 안 숨긴다** —
숨길 이유를 도구가 알 수 없기 때문이다.

| 숨기는 것 | 왜 |
|---|---|
| `code.function` · `code.namespace` | span 이름을 그대로 다시 적는다 (`OrderService.findOne` 옆에 `code.function=findOne`). **실제로 겹칠 때만** 숨기므로, span 이름을 다르게 붙이면 그대로 남는다 |
| DB span 의 `db.*`(단 `db.statement` 제외) · `server.*` | 매 쿼리마다 같은 접속 정보가 통째로 붙는다 — 호스트·포트·계정·스키마. 쿼리를 읽는 데 도움이 안 되고, `db.connection_string` 과 `server.address` 는 **내부 엔드포인트를 화면에 그대로 띄운다**(스크린샷으로 새어 나간다) |

`server.*` 는 **DB span 에서만** 숨긴다 — HTTP 호출 span 에서는 `server.address` 가
'어느 서비스가 죽었나' 라 가장 중요한 값이다. 쿼리문이 없는 DB span 이면
`db.operation`·`db.sql.table` 은 남긴다 (그마저 지우면 빈 줄이 된다).

## 설정 (⚙)

헤더 오른쪽 톱니바퀴에 있다.

| | |
|---|---|
| **테마** | 시스템 / 라이트 / 다크. '시스템' 은 OS 를 따르고, 나머지는 OS 를 무시하고 고정한다 |
| **글자 크기** | 11~15px. 작은 글씨도 함께 커진다 |
| **스택에서 하이라이트할 패키지 리스트** | 콤마로 여러 개. 예외 스택 수십 줄 중 내 코드만 밝게 본다. 비우면 안 함 |
| **소요시간 색** | 주의(노랑)·느림(빨강) 기준 ms. 바꾸면 **이미 그려진 줄도 다시 칠한다** |
| **실시간 자동 정지** | 30 / 60 / 120분 / 안 함 |
| **폴링 간격** | 3 / 5 / 10초. **CloudWatch 요청 수에 직결** — 실측상 10초면 3초의 절반 이하 |

**설정은 브라우저가 아니라 상태 디렉터리(`settings.json`)에 저장된다.** `--port` 기본값이
`0`(빈 포트 자동)이라 실행할 때마다 주소가 바뀌는데, 브라우저에 저장하면 그때마다 사라지기
때문이다. 팝오버 아래에 저장 위치가 찍혀 있다.

## 환경 변수

**우선순위: 설정(⚙) > 환경 변수 > 내장 기본값.** 환경 변수는 설정을 한 번도 안 바꿨을 때의
기본값이 된다 — 화면에서 바꾸는 순간부터는 저장값이 이긴다.

| 변수 | 뜻 |
|---|---|
| `MILOG_APP_PACKAGES` | 하이라이트할 패키지, 콤마 구분 (예: `com.acme`). **기본은 안 함** |
| `MILOG_SLOW_MS` | 느림(빨강) 기준 ms. 기본 1000 |
| `MILOG_SLOW_WARN_MS` | 주의(노랑) 기준 ms. 기본 200 |
| `MILOG_PROFILE_PREFIX` | 프로필 목록 접두어 |
| `MILOG_STATE_DIR` | 캐시·설정 파일 위치 |
| `MILOG_NO_UPDATE=1` | 자동 업데이트 끄기 |
| `MILOG_DEBUG=1` | 오류 시 스택 출력 |

## 자동 업데이트

실행할 때마다 최신 버전을 확인하고, 새 게 있으면 **시작하기 전에** 설치한다.

```
$ milog
  새 버전 1.1.0 설치 중…
  ✓ 1.1.0 으로 업데이트했습니다.
    이번 실행은 이전 버전 그대로입니다 — 다시 실행하면 새 버전으로 뜹니다.

  milog  →  http://127.0.0.1:52413/?t=…
```

끝난 뒤가 아니라 시작 전인 이유: 이 도구의 주 명령은 **웹 서버라 Ctrl+C 로만 끝난다.**
종료 시점에 걸어 두면 신호 처리 경로에서 잘려 영영 돌지 않는다.

**이때 npm 레지스트리에 통신한다.** 그 외에는 AWS 하고만 통신한다. 끄려면 `MILOG_NO_UPDATE=1`.
아래 경우에는 **확인조차 하지 않는다** — CI(`CI` 환경변수), 터미널이 아닐 때,
npm 전역 설치본이 아닐 때(소스에서 직접 실행 중일 때).

게시자가 바뀌면 설치하지 않고 경고만 한다 — 공동 관리자가 추가되거나 소유권이 넘어간 경우를 막는다.

## 안전장치

이 서버는 **당신의 AWS 자격증명으로 로그를 읽어 준다.** 그래서 아무나 못 붙게 막아 뒀다.

- **`127.0.0.1` 에만 바인딩** — 같은 네트워크의 다른 기기에서 접근 불가
- **기동할 때마다 새 토큰** — 주소에 실려 있고, 없으면 403
- **`Host` 헤더 검증** — DNS rebinding 방어
- **CORS 를 열지 않는다** — 페이지는 외부 요청이 전혀 없다 (CSP 로도 막음).
  탭 아이콘조차 인라인 SVG 라 파일을 가지러 나가지 않는다

**탭을 닫으면 폴링도 멈춘다.** 다만 **다른 탭으로 옮기는 것만으로는 안 멈춘다** —
실시간을 켜 두고 그 서비스를 보러 가는 게 가장 흔한 사용법인데, 정작 재현하는 동안
로그가 안 쌓이면 '실시간' 이 아니기 때문이다. '켜둔 채 잊기' 는 **60분 자동 정지**가 막는다.
접속이 없는 채로 `--idle-minutes` 가 지나면 서버도 스스로 종료한다.

## 비용

조회에 쓰는 `FilterLogEvents` 는 **요청당 과금이 없고**, 서버측에서 거른 뒤 매치만 전송된다.
스캔량이 아니라 **전송량(GB)** 이 비용이다 — 화면 하단에 요청 수·이벤트 수·수신량이 계속 뜬다.
